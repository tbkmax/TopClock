# Bundled add-on views

Static labels in [date.html](../date.html), [region-clock.html](../region-clock.html), and [settings-row.html](../settings-row.html) now carry explicit `data-i18n-*` keys. The [shared localization runtime](../../../i18n/doc/architecture.md) translates these build-time fragments when Alpine inserts them; reactive `x-text` labels still use `t()`. No add-on option or layout contract changed.

[counter.html](../counter.html) keeps Settings-only Reset and its confirmation dialog in [settings.html](../../../../settings.html); the instance has no Details button. [counter-details.html](../counter-details.html) owns the 0–100% Direction glow slider, bound to the app-wide `settings.counter_halo_intensity_percent` field and opened only from the Add Add-on catalog. The shared [settings row](../settings-row.html) renders Count up, Count down, and Stop from action descriptors. The [clock row](../clock-row.html) colors Counter text by signed state and gives it a spoken signed label; it does not add a modifier-click action. The [preview row](../preview-row.html) receives the same color through its style binding. Both display rows apply the `up`/`down` class and computed glow alpha to Counter's text, using [text-glow.css](../../../text-glow.css), which also styles the clock's Ctrl glow. A paired neighbor receives no glow. The fragments are selected from the fixed [registry](../../registry.js) at build time.

The glow stylesheet selects `.addon-line.addon-motion-*` and `.addon-preview-line.addon-motion-*` explicitly. These selectors outrank the clock's later base text-shadow rule in the production bundle. The glow colors are lighter blue/red shades of the [DESIGN.md](../../../../doc/DESIGN.md) accents; Counter's signed text color is independent.

The Counter selectors set 4px and 8px blur distances to keep the glow close to its smaller text. The Ctrl-held clock leaves those variables unset and keeps the 10px and 20px defaults in the same CSS rule.


[timer.html](../timer.html) keeps its mode selector active while running and opens Timer's own [timer-details.html](../timer-details.html) in countdown mode. The Details fragment edits Timer presets and can re-enable both Timer reset warnings through Settings' save controller. It reuses the visual classes of the Progress preset editor; Timer and Progress fields and modal states stay separate. The fixed fragment registry includes the new file at build time, with no runtime HTML loading.

[region-clock.html](../region-clock.html) renders an Alpine combobox only for a Region instance. Its bounded listbox shows city/country labels and the exact IANA ID; the text field matches country, city, or ID and supports arrow keys, Enter, Escape, and pointer selection. The [Settings-only picker](../../builtins/region-picker.js) owns transient search state and the localized search records. The view calls `editAddonOption` only for a selected ID. [settings.css](../../../settings/settings.css) keeps results within the card's document flow so they remain scrollable in the fixed Settings window.

The [Settings row](../settings-row.html) renders one member inside a single or combined card, with its own enabled switch in either case. [settings.html](../../../../settings.html) owns the paired card's group control, shared scale, Split control, and Edit/Done button. [settings.css](../../../settings/settings.css) places its two member panels in equal left/right columns and stretches them to the same height so the center divider stays continuous. The group switch is visually on when either member is enabled. One card-local `expanded` flag shows both editors together; single cards use the same flag for their own editor. [clock-row.html](../clock-row.html) and [preview-row.html](../preview-row.html) are repeated in a centered layout row derived by [layout.js](../../layout.js); a hidden partner leaves one visible member. These static fragments still receive only text-bound runtime values.

[progress.html](../progress.html) adds a Details button for each Progress instance. The catalog card in [settings.html](../../../../settings.html) offers Details at the far right of a reserved action slot, while Add stays at the left edge of every card. Both entries call the generic Settings detail method. [progress-details.html](../progress-details.html) contains the shared preset editor and warning preference; values are text-bound and neither entry owns another copy.

These fragments contain static Alpine markup for the clock and Settings. See the [host architecture](../../doc/architecture.md) and [frontend architecture](../../../doc/architecture.md) for their data sources.

[clock-row.html](../clock-row.html) owns the shared clock row and its click boundary. All five current add-ons return text, time parts, or progress data that this row can display. A later compiled type can register a special clock view without changing the row. [settings-row.html](../settings-row.html) owns the configured row, size, drag handle, enable switch, and action buttons. [preview-row.html](../preview-row.html) is reused above and below the preview clock. [date.html](../date.html), [region-clock.html](../region-clock.html), [timer.html](../timer.html), [progress.html](../progress.html), and [counter.html](../counter.html) contain the type-specific Settings controls; Counter, Timer, and Progress also contribute allowlisted Details fragments. The type slots expand from the fixed [registry](../../registry.js).

[build-fragments.js](../../build-fragments.js) reads only registered files beneath this folder and inserts them through Vite's `transformIndexHtml` step in development and production. Missing or unknown slots fail. Alpine receives the composed markup before initialization; no runtime `x-html`, remote template, settings-provided markup, or arbitrary include path is used. Runtime values use text and attribute bindings. `x-for` keeps one row root and type fragments inherit the row's `addon` scope. Static IDs and per-instance IDs remain distinct.

The host owns action availability. Views call the page's add-on host methods and do not invoke Tauri commands directly. [style.css](../../../style.css), [settings.css](../../../settings/settings.css), and Progress's [progress.css](../../builtins/progress.css) style the assembled views.
