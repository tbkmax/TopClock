# Frontend architecture

The clock menu runs in its own hidden `menu` webview, with markup in [menu.html](../../menu.html), behavior in [menu.js](../menu.js), and styles in [menu.css](../menu.css). Ctrl-right-click sends a screen anchor to Rust; the menu webview renders registered add-on entries, measures its content, and asks Rust to fit the window inside the nearest display. Clock sizing and saved clock position do not incorporate menu geometry. Progress rows show white instance names, a yellow Start/Pause action, a quieter Reset action, and a Set disclosure with distinct preset chips. Preset confirmation and the saved warning preference remain per the native `progress_timer_set_preset` transaction. [settings.js](../settings.js) opens the same shared Progress details view from the catalog and each instance; the definition declares its optional detail fragment, so future compiled add-ons can add one without duplicating catalog wiring.

The Settings preview uses [settings-preview.js](../settings-preview.js) to keep one 200 ms timer while the native window is visible and restored. [settings.js](../settings.js) refreshes this state on focus and resize events, after initialization, and after successful hide/minimize commands. A monotonically increasing request number discards stale asynchronous visibility results. Hidden previews skip renders triggered by settings/timer events too; the underlying settings and sessions still update. Reopening renders the current time immediately. Native visibility is authoritative because a hidden WebView2 document can report itself visible. See the [native architecture](../../src-tauri/src/doc/architecture.md) for window ownership.

[main.js](../main.js) resizes each clock only to its clock content through [clock-layout.js](../clock-layout.js), preserving the existing unrestricted placement and digit anchor. [menu.js](../menu.js) owns menu expansion, confirmation, Escape handling, and native show/close requests. Native input polling dismisses on outside presses or a foreground change; it does not alter the clock's click-through rule. See the [native menu workflow](../../src-tauri/src/doc/workflow_diagram.md).

General saves `language` as `system`, `en`, `zh-Hans`, `zh-Hant`, or `ja` in shared `ClockSettings`. Both Alpine pages ask Rust for the preferred Windows UI language through `get_system_locale`, then [i18n.js](../i18n.js) maps it to a supported language when the preference is `system`. An unsupported UI language falls back to English. Static markup text and attributes are translated from bundled strings, including newly inserted Alpine templates; reactive labels use `t()`. Changing the preference previews the clock language immediately and persists through the existing save controller. The Date add-on's weekday uses `Intl.DateTimeFormat` in the effective language while numeric date options and time layouts keep their saved format. Both pages set their HTML `lang` attribute. The native tray has its own small translation table; see [native architecture](../../src-tauri/src/doc/architecture.md).

The General tab's Settings files button invokes `open_settings_folder`; Rust opens the app config directory containing `settings.json` in Windows Explorer. The frontend does not construct a filesystem path.

The General tab groups connected desktop displays separately from app behavior settings. It lists displays from `get_displays` and persists each switch through `set_display_enabled`. [settings.js](../settings.js) removes the Windows `\\.\` device prefix and formats `DISPLAY1` as `Display 1` for visible labels and switch accessibility names; the original display ID remains the command and persistence key. Missing display preferences mean visible, including newly connected displays. All clock windows load the same `ClockSettings`, numeric Timer session, and Progress countdown sessions; Settings broadcasts `clock-settings-preview` to every clock, and Rust broadcasts saved settings and session events. Only visibility and a display-relative position vary by display. Each clock instance receives its own proximity and modifier events. Direct pointer dragging and resize anchoring do not clamp the window to a display, preserving edge placement. Rust owns display identity, hot-plug reconciliation, and durable positions; see the [native architecture](../../src-tauri/src/doc/architecture.md).

At the bottom of the Clock tab, Reset positions calls `reset_clock_positions` to center the clocks currently visible on connected displays. The command saves each centered position; a display switched off in General keeps its previous position. The button disables while the command runs and reports failures through the Settings error toast.

This folder owns three Alpine.js page types: Settings, a clock page instantiated once per enabled display, and the separate menu. Read the [README](../../README.md) and [Tauri architecture](../../src-tauri/doc/architecture.md) for the native boundary.

[index.html](../../index.html) and [settings.html](../../settings.html) supply markup; [vite.config.js](../../vite.config.js) declares both entries. Rust validates and persists settings. Frontend code does not write the settings file or registry. The clock receives `ctrl-state`, `proximity`, `clock-settings-preview`, `clock-settings-changed`, and `timer-state-changed`. Settings receives `hotkey-errors-changed`. A preview event shows a draft change before Rust saves it. `settings-persistence.js` keeps a separate committed snapshot. If the latest command fails, Settings reads back the native settings: a matching draft counts as saved, while a different result restores native settings and the Timer session to the UI and broadcasts the recovered settings to every clock. The committed snapshot is a fallback if readback fails. Both pages use `timeParts` and `markChangedNumbers`; a region clock passes a named time zone to `timeParts` and inherits the main clock's appearance and animation choices. The Settings page asks Rust for installed fonts and uses Segoe UI or another installed font if the saved family is unavailable. No network font is requested.

The fixed [registry](../addons/registry.js) and [type definitions](../addons/builtins/doc/architecture.md) own Date, Region clock, Timer, and Progress defaults, display formatting, Settings rules, and action descriptors. [model.js](../addons/model.js) creates instances and shared display results. [host.js](../addons/host.js) gives [controller.js](../addons/controller.js) and the page one reactive session object; [state.js](../addons/state.js) accepts native events, rejects stale responses, and disposes subscriptions. [build-fragments.js](../addons/build-fragments.js) inserts only bundled view files at build time, without runtime HTML injection. Instances in `settings.addons` have stable IDs, kind, enabled state, above/below placement, relative text size from 10% to 100%, and options. New instances start at 30%. The [Settings dashboard](../../settings.html) lists configured instances first, with a clock block between the above and below stacks. Each row shows a name, subtitle, size, enable switch, and drag handle; its editing controls start collapsed and open independently. The handle captures pointer movement, so the card follows the pointer; releasing over the upper or lower half of a row places an add-on before or after it, while releasing over the clock block places it at the end of the above stack or start of the below stack. Arrow keys on the focused handle offer the same adjacent moves, including crossing the clock. [instance-editor.js](../addons/instance-editor.js) changes the saved placement and array order together, then uses the existing save controller. The clock block and drag target are UI-only; they are not persisted as add-ons. The add catalog follows the list, starts open only when the list is empty, and has a bounded scrolling area for more catalog types. Its top shortcut scrolls to it. The live desktop layout preview follows the catalog and starts collapsed. Disclosure states are local UI state and are not saved. A Date can append an optional, smaller localized short weekday after the date; a Region clock can hide its region label. Existing Date and Region instances retain their former display when these optional settings are absent. Timer rows show the elapsed or remaining time without a mode label. Multiple region and Progress instances are allowed; Date and Timer are singletons. Normal flex layout prevents add-ons from covering each other, and the above-stack gap is shortened to balance the space around the main clock. [main.js](../main.js) measures the whole group and menu, resizes the transparent native window, and preserves the main clock's top and right screen coordinates without display-edge clamping. Modifier-click on Timer or a Progress countdown invokes its native action without toggling the clock format. The menu offers Reset timer only while Timer is enabled. Rust owns durable timer progress and countdown completion; see [native architecture](../../src-tauri/src/doc/architecture.md).

Each webview constructs one add-on host with an Alpine-reactive session snapshot. The controller, clock rendering, Settings preview, and Start/Pause labels read that same object. The pages expose read-only Timer and Progress getters for existing templates and editors but do not keep separate session copies. Native events and action results update the host; revision checks prevent stale command responses from replacing newer events.

Progress options retain date, daily-time, and countdown values when switching modes. Date mode defaults to today through tomorrow and advances by local calendar days, reaching 100% on the end date. Time mode holds 1–8 ranges ordered by start time, each ending on the same day; ranges may overlap only when their weekday sets do not intersect; each range may save a `days` array of weekday codes (`sun` through `sat`). Missing or empty `days` means every day, including existing saved ranges. Settings shows a compact week grid with one row per range and seven localized weekday columns. A time row opens a small editor for its start and end; the grid toggles days directly and keeps at least one day selected. An overlap on a shared weekday is rejected in both frontend and Rust validation. Each scheduled range gets its own bar, remains complete after its end, and resets at midnight. Unscheduled ranges are omitted; a day with no scheduled ranges hides the Progress instance. Auto-hide uses the last range scheduled for the current day. Countdown mode has a duration and an independent native session per Progress instance; its single bar fills from empty to full as time elapses. Settings provides Start/Pause and Reset, and modifier-click on that clock bar toggles its session. The Minutes field saves valid edits before the first Start and after finish or Reset. Once started, it stays locked through Pause and restart; the hint explains when it unlocks. The numeric Timer remains separate. Clock and preview bars have no visible captions; a per-instance percentage switch defaults off. Per-instance length defaults to 85% of the prior responsive width, while thickness defaults to 100% of the prior responsive height; Settings sliders adjust both independently. Missing appearance fields in older Progress instances use those defaults. The phase colors are gray, yellow, rose, and green. Daily ranges and countdown completion have a brief pulse; optional auto-hide applies only to daily ranges. [Progress calculations](../addons/builtins/progress-display.js) calculates display values and responsive dimensions from current time and saved sessions. Rust persists countdown sessions and validates options. The existing 16-instance limit applies to all kinds. [progress.css](../addons/builtins/progress.css) styles both views and honors reduced-motion preference. See the [progress plan](../../doc/feature/PROGRESS_ADDON_PLAN.md) for verified checks and the live verification gap.

The configured interaction modifier remains active for drag and the clock menu while native click-through is otherwise preserved. Action shortcuts are individually off by default and registered system-wide by Rust only when switched on. The Shortcuts tab records bindings and reports internal duplicates and Windows registration failures. Timer bindings are editable only while Timer is enabled. The main clock's keyboard listener handles modifier state and Escape; it does not dispatch action shortcuts, avoiding duplicate actions. The Settings clock preview caps font size at 64 pixels. General asks Rust whether the process has package identity. A direct build labels its check as GitHub Releases; **View GitHub release** opens the browser without installing. A packaged build labels its check as Microsoft Store; when Rust reports a published update, **Update** requests Store download and installation with a Windows permission dialog. Both current-version messages identify their source. Launching the staged executable directly has no package identity and follows the GitHub path. Store installation remains unverified with a Store-signed package. The sidebar alert badge appears only when `updateAvailable` is true. The sign-in switch reads native state again after a change so Windows' user-disabled state is reported rather than displayed as enabled.

Settings uses an ARIA tablist and keeps all four panels mounted, showing only the selected panel. Arrow keys move between tabs, and Home and End select the first and last tabs. The Shortcuts tab renders its four actions from `shortcutGroups`, with one shared row template and a separate interaction-modifier control. `npm run test:frontend` runs the shared frontend and colocated add-on tests without a browser or native Tauri process; `npm run build` checks both Vite entries.
