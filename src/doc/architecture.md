# Frontend architecture

This folder owns the two Alpine.js interfaces. Read the [README](../../README.md) and [Tauri architecture](../../src-tauri/doc/architecture.md) for the native boundary.

| File | Responsibility |
| --- | --- |
| [main.js](../main.js) | Clock parts, add-on stack rendering, anchored window resizing, modifier interaction, drag, menu and native events |
| [addons.js](../addons.js) | Built-in add-on catalog, instance defaults, local date, region time and timer display helpers |
| [time-format.js](../time-format.js) | Shared time layout presets, unpadded hours, two-digit minutes and seconds, and local font fallback |
| [clock-animations.js](../clock-animations.js) | Independent colon and number animation options, plus per-number change tracking shared by both windows |
| [style.css](../style.css) | Transparent clock appearance, natural-width time segments, animation variants and proximity fade |
| [settings.js](../settings.js) | Clock and add-on previews, add-on dashboard, save queue, timer mode confirmation, shortcut switches and conflict detection, startup and update controls |
| [settings.css](../settings.css) | Settings page layout, controls, shortcut key pill styles, conflict alerts, and update action buttons |

[index.html](../../index.html) and [settings.html](../../settings.html) supply markup; [vite.config.js](../../vite.config.js) declares both entries. Rust validates and persists settings. Frontend code does not write the settings file or registry. The clock receives `ctrl-state`, `proximity`, `clock-settings-preview`, `clock-settings-changed`, and `timer-state-changed`. Settings receives `hotkey-errors-changed`. A preview event can show a change before Rust saves it. Both pages use `timeParts` and `markChangedNumbers`; a region clock passes a named time zone to `timeParts` and inherits the main clock's appearance and animation choices. The Settings page asks Rust for installed fonts and uses Segoe UI or another installed font if the saved family is unavailable. No network font is requested.

The add-on catalog in [addons.js](../addons.js) defines Date, Region clock, and Timer defaults and display formatting. Instances in `settings.addons` have stable IDs, kind, enabled state, above/below placement, relative text size from 10% to 100%, and options. New instances start at 30%. The Settings dashboard changes these values and previews the same two-stack order used by [index.html](../../index.html). A Date can append an optional, smaller three-letter English weekday after the date; a Region clock can hide its region label. Existing Date and Region instances retain their former display when these optional settings are absent. Timer rows show the elapsed or remaining time without a mode label. Multiple region instances are allowed; Date and Timer are singletons. Normal flex layout prevents add-ons from covering each other, and the above-stack gap is shortened to balance the space around the main clock. [main.js](../main.js) measures the whole group and menu, resizes the transparent native window, and preserves the main clock's top and right screen coordinates where monitor bounds permit. Modifier-click on Timer invokes native timer actions without toggling the clock format. The menu offers Reset timer only while Timer is enabled. Rust owns durable timer progress and countdown completion; see [native architecture](../../src-tauri/src/doc/architecture.md).

The configured interaction modifier remains active for drag and the clock menu while native click-through is otherwise preserved. Action shortcuts are individually off by default and registered system-wide by Rust only when switched on. The Shortcuts tab records bindings and reports internal duplicates and Windows registration failures. Timer bindings are editable only while Timer is enabled. The main clock's keyboard listener handles modifier state and Escape; it does not dispatch action shortcuts, avoiding duplicate actions. The Settings clock preview caps font size at 64 pixels. The General tab queries GitHub Releases when update checks are enabled and can open the release page in the default browser. Its sidebar tab shows an alert badge whenever `updateAvailable` is true; a later successful check clears that state when the installed version is current.
