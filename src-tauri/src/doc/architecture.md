# Rust application architecture

[locale.rs](../locale.rs) exposes `get_system_locale`. On Windows it reads the first preferred user UI language as a BCP 47 name, falling back to the user's regional locale and then English if necessary. This applies to direct and MSIX launches. [settings.rs](../settings.rs) adds a validated, serde-defaulted `language` field with `system` as the default for old settings files. [settings_commands.rs](../settings_commands.rs) persists language changes with the other settings; [tray.rs](../tray.rs) builds the initial localized Quit item and tooltip, then updates them when a saved language choice changes. Frontend translation strings and weekday formatting live in [src/i18n.js](../../../src/i18n.js). The OS locale is read, not persisted.

[webview_runtime.rs](../webview_runtime.rs) checks for the Evergreen WebView2 Runtime before [lib.rs](../lib.rs) creates any webview. When unavailable, it shows a native message with Microsoft's download page and exits. The runtime is not bundled with MSIX or direct builds.

The `open_settings_folder` command in [window_commands.rs](../window_commands.rs) uses the managed settings path, ensures its parent exists, and launches that directory in Windows Explorer. It does not accept a caller-supplied path.

`display_identity.rs` queries active Windows display targets and maps their device paths to Tauri's GDI display names. [displays.rs](../displays.rs) reconciles one transparent clock window per enabled desktop display every two seconds, creating and removing secondary windows as displays change. Target paths identify saved display preferences; a monitor moved to another connector can receive a different path. When Windows supplies no target path, a GDI display slot is the fallback and may change after reordering. Each display preference stores an independent visible flag and position relative to that display's origin, without restricting that position to the display. Missing preferences default to visible, including newly connected displays. The legacy absolute `position` is migrated to the matching display on first startup. `ClockSettings` and `TimerSession` remain shared across all clocks; each window has its own menu flag, click-through and proximity state.

`reset_clock_positions` in [displays.rs](../displays.rs) centers each currently visible clock using that window's physical size and its active display's physical bounds. It saves the resulting display-relative positions together. A display disabled in General retains its previous position. If a window move or config save fails, the command attempts to restore moved windows; the Settings UI receives an error. This command does not alter click-through styles or display visibility.

[main.rs](../main.rs) is the binary entry point. [lib.rs](../lib.rs) registers commands and wires startup in order. [state.rs](../state.rs) owns shared in-process state; [config_store.rs](../config_store.rs) loads, migrates, validates, and saves the durable config. [settings.rs](../settings.rs) owns its schema, defaults, and validation. [addons.rs](../addons.rs) validates built-in add-on instances and calculates Timer sessions; [timer.rs](../timer.rs) applies Timer actions and emits session changes. [displays.rs](../displays.rs) owns display window lifecycle and positions, while [interaction.rs](../interaction.rs) polls input and applies native click-through. [settings_commands.rs](../settings_commands.rs), [window_commands.rs](../window_commands.rs), [startup.rs](../startup.rs), and [store_updates.rs](../store_updates.rs) expose the related Tauri commands. [tray.rs](../tray.rs) builds the tray. [hotkeys.rs](../hotkeys.rs) registers enabled action shortcuts with Windows. [fonts.rs](../fonts.rs) enumerates Windows-installed fonts. The parent [Tauri architecture](../../doc/architecture.md) describes package configuration.

| Unit | Responsibility |
| --- | --- |
| `ClockState` in `state.rs` | In-process config mutex, per-window menu flags, active display windows, settings path and hotkey errors |
| `PersistedConfig` | Shared clock settings and Timer session, per-display preferences and legacy position, defined in `settings.rs` |
| `AddonInstance` | ID, type, enable state, above/below placement, size percentage and validated type options |
| `TimerSession` | Durable running flag, accumulated elapsed time, start epoch and finished state |
| `get_font_families` | Read and deduplicate font families from the Windows GDI font table |
| Tauri commands | Shared settings and Timer actions, per-display visibility, bounds and position reset, package-aware sign-in switch, package identity query, Store update check and install request, menu state, window controls, folder and direct-build release page opening, and quit; registered in `lib.rs` |
| `start_monitor` in `interaction.rs` | Poll configured modifier key (Ctrl, Alt, or Shift), cursor proximity and window position; set click-through and emit events; call Timer completion in `timer.rs` |
| `start_hotkeys` | Register enabled system-wide action shortcuts, dispatch their native actions, and report unavailable combinations |
| `set_click_through` | Toggle Win32 `WS_EX_TRANSPARENT` while preserving `WS_EX_LAYERED`, then refresh the window frame so the input style takes effect without the earlier GDI white flash |
| Tray setup in `tray.rs` | Open settings and quit actions |

At startup, `lib.rs` asks `config_store.rs` to load `settings.json` from Tauri's app config directory (`%APPDATA%\topclock\settings.json`), migrating from legacy `com.maxtc.topclock` if present. It defaults missing fields, salvages unrelated clock settings if add-on data cannot deserialize, and clears semantically invalid add-on instances without resetting valid clock appearance. The old `timer_addon_enabled` flag becomes a Countdown add-on once. An older default `Ctrl+Q` Quit binding becomes `Ctrl+Alt+Q`; action shortcuts get off-by-default enable flags. Rust writes the config, builds the configured `main` and `settings` webviews, then reconciles enabled display clocks. A display with no saved position starts near its top-right corner.

The current settings schema includes clock appearance, time layout, animation choices, update preference, `shortcuts`, `addons`, and a saved warning dismissal for Timer mode changes. `addons` is an ordered list; Date and Timer allow one instance each, Region clock allows up to 12, Progress can repeat, and the overall limit is 16. [addons.rs](../addons.rs) validates IDs, type-specific options, placement and relative text size from 10% through 100%. Date accepts an optional boolean `show_weekday`; Region clock accepts an optional boolean `show_label`. Omitting these fields remains valid for saved instances created before the switches existed. Progress has a date/time mode, two valid ordered dates, 1–8 ordered same-day nonoverlapping time ranges, and an auto-hide boolean; both mode values remain saved so switching modes preserves prior edits. Progress may also save optional `show_percentage`, `bar_length_percent` (50–150), and `bar_thickness_percent` (50–200) fields. Omitting them remains valid for Progress instances saved before the appearance controls; the frontend supplies off, 85%, and 100% defaults respectively. Rust checks this saved configuration only. [progress.js](../../../src/progress.js) calculates each bar from local time without a native session or new command. The legacy Timer migration creates an instance at 30%; existing saved sizes are preserved. Adding a similar built-in type requires one validation branch and a frontend catalog/formatter entry; saved data cannot execute code. `update_settings` rejects invalid changes, rolls back memory on write failure, and emits `clock-settings-changed`. A running Timer cannot change its mode or duration. Its `TimerSession` is separate from appearance settings, persists on Start/Pause/Reset, and uses the stored wall-clock start time to resume after restart. The monitor marks a Countdown finished at zero and emits `timer-state-changed`.

The configured modifier key is polled by `interaction::start_monitor` for each clock window and stays active for dragging and its menu. Display reconciliation enables click-through before showing a clock; the monitor reconciles the visible window on its first poll. Later polls toggle `WS_EX_TRANSPARENT` only when needed, retain `WS_EX_LAYERED`, send `ctrl-state` and `proximity` to that clock, and save its display-relative position after movement settles. Saved positions restore without edge clamping. [hotkeys.rs](../hotkeys.rs) registers enabled action bindings once for the application. [startup.rs](../startup.rs) uses `GetCurrentPackageFullName` to select Windows StartupTask for an MSIX or the existing HKCU Run key for a direct build. A Windows user-disable state returns a message directing the user to Windows Startup settings; the app does not override it. [store_updates.rs](../store_updates.rs) rejects direct builds, initializes StoreContext with the Settings window as its dialog owner on the UI thread, and asks the Store for available packages or installation. [window_commands.rs](../window_commands.rs) refuses to open the GitHub release page when packaged.

The command and event boundary is used by [frontend code](../../../src/doc/architecture.md). [default.json](../../capabilities/default.json) lists frontend permissions. Unit tests cover settings validation, add-on validation, Timer resume/completion, hotkey parsing and font enumeration. The font list is read on request, while only the selected family name is persisted. These built-in add-ons do not load third-party code or network data.
