# Rust application architecture

`ClockSettings` now includes a separate `timer_countdown_presets` list and `timer_preset_warning_dismissed` flag, defaulted for older settings files. Both Timer and Progress lists use the same bounded sorted-minute validator. [timer.rs](../timer.rs) exposes `timer_set_mode` and `timer_set_preset`; [addons/actions.rs](../addons/actions.rs) validates the enabled Timer, the choice and confirmation under one config lock. A mode switch clears its session, while a countdown preset clears and starts a new session. One settings write precedes both `clock-settings-changed` and `timer-state-changed`; write failure restores settings and session. Progress fields, sessions, and commands remain separate.

`ClockSettings.addon_pairs` is an optional list of two-member layout links alongside the existing flat `addons` list. [addons/instance.rs](../addons/instance.rs) validates adjacent IDs, matching placement and enabled flags, eligible non-Progress kinds, unique membership, and a 10–100% shared scale. [settings_commands.rs](../settings_commands.rs) rejects an invalid draft in the normal atomic save path. [config_store.rs](../config_store.rs) discards malformed or stale pair links on load while retaining the individual add-ons, so a build that does not know pairing can still load and save their existing records. Saving in that older build loses only the pair metadata. Timer and Progress sessions continue to key off instance IDs.

Shared `ClockSettings` now stores `progress_countdown_presets` (a sorted list of up to eight unique whole minutes from 1 to 5999) and `progress_preset_warning_dismissed`; older files default to `[10, 30, 60]` and false. [timer.rs](../timer.rs) exposes `progress_timer_set_preset`, while [addons/actions.rs](../addons/actions.rs) validates the chosen preset and enabled countdown ID, checks for confirmation if elapsed progress would be cleared, and atomically saves the new duration, restarted session, and optional warning dismissal. It rolls back memory on write failure and emits both settings and Progress-session events after success. Other Progress sessions and the numeric Timer are unchanged.

Startup settings persistence and legacy position migration are best-effort writes. [lib.rs](../lib.rs) and [displays.rs](../displays.rs) log write errors and continue with the loaded/normalized in-memory configuration, allowing the clock to open when its settings file is temporarily locked or unwritable. Later user-initiated saves retain their existing validation/error behavior. Other fatal window/runtime initialization errors still propagate through Tauri startup.

[menu_window.rs](../menu_window.rs) owns a separate menu window request and physical display-edge fitting. It receives a logical click anchor from a clock, converts it to screen coordinates, and positions only the `menu` webview. The request ID prevents a stale close from dismissing a newer menu. [interaction.rs](../interaction.rs) keeps the clock's click-through rule tied only to the modifier. Its 30 ms per-clock monitor observes new presses outside the menu window and foreground changes; `MenuDismissal` ignores held buttons and releases. It emits `dismiss-menu` to the menu webview. Hidden polls reset observation state.

The frontend closes through `close_clock_menu`; the clock's click-through continues to follow the modifier independently. Observation does not hook, capture or suppress another application's input, add threads, or persist state. Only the reliable current-state high bit of `GetAsyncKeyState` is used. Very short clicks can fall between samples, and sampled pointer coordinates can differ from the exact press location. See the [investigation, alternatives and acceptance checks](../../../doc/report/CONTEXT_MENU_FIX.md) and [parent package architecture](../../doc/architecture.md).

[topmost.rs](../topmost.rs) restores each visible, non-minimized clock's native Z order. The existing per-clock [interaction monitor](../interaction.rs) schedules a refresh on the first visible poll and every two seconds afterward; hidden polls reset the schedule. The UI-thread callback resolves the current HWND, checks visibility/minimization again, and calls `SetWindowPos(HWND_TOPMOST)` with `SWP_NOACTIVATE | SWP_NOMOVE | SWP_NOSIZE | SWP_NOOWNERZORDER`. It does not rewrite layered/click-through styles, change focus, or show windows. Direct native recovery is necessary because the bundled Tao implementation caches its always-on-top flag and can skip repeated `true` requests. Reassertion also handles a clock still marked topmost but covered by another topmost window. Failed dispatch/native calls are reported to stderr and retried at the next interval. No settings, commands, events, capabilities, or extra worker threads are added. This is desktop Z-order recovery, not a guarantee over exclusive-fullscreen rendering or secure desktops; see the [investigation and risks](../../../doc/report/TOPMOST_RECOVERY.md).

[locale.rs](../locale.rs) exposes `get_system_locale`. On Windows it reads the first preferred user UI language as a BCP 47 name, falling back to the user's regional locale and then English if necessary. This applies to direct and MSIX launches. [settings.rs](../settings.rs) adds a validated, serde-defaulted `language` field with `system` as the default for old settings files. [settings_commands.rs](../settings_commands.rs) persists language changes with the other settings; [tray.rs](../tray.rs) builds the initial localized Quit item and tooltip, then updates them when a saved language choice changes. Frontend translation strings and weekday formatting live in [src/i18n.js](../../../src/i18n.js). The OS locale is read, not persisted.

[webview_runtime.rs](../webview_runtime.rs) checks for the Evergreen WebView2 Runtime before [lib.rs](../lib.rs) creates any webview. When unavailable, it shows a native message with Microsoft's download page and exits. The runtime is not bundled with MSIX or direct builds.

The `open_settings_folder` command in [window_commands.rs](../window_commands.rs) uses the managed settings path, ensures its parent exists, and launches that directory in Windows Explorer. It does not accept a caller-supplied path.

`display_identity.rs` queries active Windows display targets and maps their device paths to Tauri's GDI display names. [displays.rs](../displays.rs) reconciles one transparent clock window per enabled desktop display every two seconds, creating and removing secondary windows as displays change. Target paths identify saved display preferences; a monitor moved to another connector can receive a different path. When Windows supplies no target path, a GDI display slot is the fallback and may change after reordering. Each display preference stores an independent visible flag and position relative to that display's origin, without restricting that position to the display. Missing preferences default to visible, including newly connected displays. The legacy absolute `position` is migrated to the matching display on first startup. `ClockSettings` and `TimerSession` remain shared across all clocks; the menu request records one owning clock while each clock has its own click-through and proximity state.

`reset_clock_positions` in [displays.rs](../displays.rs) centers each currently visible clock using that window's physical size and its active display's physical bounds. It saves the resulting display-relative positions together. A display disabled in General retains its previous position. If a window move or config save fails, the command attempts to restore moved windows; the Settings UI receives an error. This command does not alter click-through styles or display visibility.

[main.rs](../main.rs) is the binary entry point. [lib.rs](../lib.rs) registers commands and wires startup in order. [state.rs](../state.rs) owns shared in-process state; [config_store.rs](../config_store.rs) loads, migrates, validates, and saves the durable config. [settings.rs](../settings.rs) owns its schema, defaults, and validation. [addons/](../addons/doc/architecture.md) contains the static kind registry, type validators, shared Timer session calculations, and typed action service; [timer.rs](../timer.rs) keeps compatibility commands and main-window completion monitoring. [displays.rs](../displays.rs) owns display window lifecycle and positions, while [interaction.rs](../interaction.rs) polls input and applies native click-through. [settings_commands.rs](../settings_commands.rs), [window_commands.rs](../window_commands.rs), [startup.rs](../startup.rs), and [store_updates.rs](../store_updates.rs) expose the related Tauri commands. [tray.rs](../tray.rs) builds the tray. [hotkeys.rs](../hotkeys.rs) registers enabled action shortcuts with Windows. [fonts.rs](../fonts.rs) enumerates Windows-installed fonts. The parent [Tauri architecture](../../doc/architecture.md) describes package configuration.

| Unit | Responsibility |
| --- | --- |
| `ClockState` in `state.rs` | In-process config mutex, current menu request, owning clock, active display windows, settings path and hotkey errors |
| `PersistedConfig` | Shared clock settings, numeric Timer session, per-ID Progress countdown sessions, per-display preferences and legacy position, defined in `settings.rs` |
| `AddonInstance` | ID, type, enable state, above/below placement, size percentage and validated type options |
| `TimerSession` | Durable running flag, accumulated elapsed time, start epoch, finished state, and Progress first-Start lock flag |
| `get_font_families` | Read and deduplicate font families from the Windows GDI font table |
| Tauri commands | Shared settings and Timer actions, per-display visibility, bounds and position reset, package-aware sign-in switch, package identity query, Store update check and install request, menu window lifecycle, window controls, folder and direct-build release page opening, and quit; registered in `lib.rs` |
| `start_monitor` in `interaction.rs` | Poll configured modifier key (Ctrl, Alt, or Shift), cursor proximity and window position; set click-through and emit events; call Timer completion in `timer.rs` |
| `start_hotkeys` | Register enabled system-wide action shortcuts, dispatch their native actions, and report unavailable combinations |
| `set_click_through` | Toggle Win32 `WS_EX_TRANSPARENT` while preserving `WS_EX_LAYERED`, then refresh the window frame so the input style takes effect without the earlier GDI white flash |
| Tray setup in `tray.rs` | Open settings and quit actions |

At startup, `lib.rs` asks `config_store.rs` to load `settings.json` from Tauri's app config directory (`%APPDATA%\topclock\settings.json`), migrating from legacy `com.maxtc.topclock` if present. It defaults missing fields, salvages unrelated clock settings if add-on data cannot deserialize, and clears semantically invalid add-on instances without resetting valid clock appearance. The old `timer_addon_enabled` flag becomes a Countdown add-on once. An older default `Ctrl+Q` Quit binding becomes `Ctrl+Alt+Q`; action shortcuts get off-by-default enable flags. Rust writes the config, builds the configured `main` and `settings` webviews, then reconciles enabled display clocks. A display with no saved position starts near its top-right corner.

The current settings schema includes clock appearance, time layout, animation choices, update preference, `shortcuts`, `addons`, and separate Timer and Progress preset lists and warning preferences. `addons` is an ordered list; Date and Timer allow one instance each, Region clock allows up to 12, Progress can repeat, and the overall limit is 16. [addons/](../addons/doc/architecture.md) validates IDs, type-specific options, placement and relative text size from 10% through 100%. Date accepts an optional boolean `show_weekday`; Region clock accepts an optional boolean `show_label`. Omitting these fields remains valid for saved instances created before the switches existed. Progress has date, daily-time, and countdown modes, two valid ordered dates, 1–8 same-day time ranges ordered by start time, and an auto-hide boolean; all mode values remain saved so switching modes preserves prior edits. Each time range may carry a `days` array with unique `sun` through `sat` weekday codes. Missing or empty `days` retains everyday behavior for older saved ranges. Ranges may overlap in time only when their weekday sets do not intersect. Missing or empty weekday arrays count as all seven days during overlap validation. Progress may also save optional `show_percentage`, `bar_length_percent` (50–150), and `bar_thickness_percent` (50–200) fields. Omitting them remains valid for Progress instances saved before the appearance controls; the frontend supplies off, 85%, and 100% defaults respectively. Rust validates countdown duration and stores a separate **TimerSession** per Progress ID in **progress_timer_sessions**. Its saved **has_started** flag keeps Minutes locked through Pause and restart; finish or Reset unlocks editing. **progress_timer_action** persists each session and emits **progress-timer-states-changed**; [Progress calculations](../../../src/addons/builtins/progress-display.js) calculates date and daily bars from local time and countdown fill from the saved session. The legacy Timer migration creates an instance at 30%; existing saved sizes are preserved. Adding a similar compiled type requires a native validator/handler registration and a frontend definition/view; saved data cannot execute code. `update_settings` rejects invalid changes, rolls back memory on write failure, and emits `clock-settings-changed`. A running Timer can change mode through the confirmed native command; changing its duration in Settings still requires a pause. Its `TimerSession` is separate from appearance settings, persists on Start/Pause/Reset, and uses the stored wall-clock start time to resume after restart. The monitor marks a Countdown finished at zero and emits `timer-state-changed`.

The configured modifier key is polled by `interaction::start_monitor` for each clock window and stays active for dragging and its menu. Display reconciliation enables click-through before showing a clock; the monitor reconciles the visible window on its first poll. Later polls toggle `WS_EX_TRANSPARENT` only when needed, retain `WS_EX_LAYERED`, send `ctrl-state` and `proximity` to that clock, and save its display-relative position after movement settles. Saved positions restore without edge clamping. [hotkeys.rs](../hotkeys.rs) registers enabled action bindings once for the application. [startup.rs](../startup.rs) uses `GetCurrentPackageFullName` to select Windows StartupTask for an MSIX or the existing HKCU Run key for a direct build. A Windows user-disable state returns a message directing the user to Windows Startup settings; the app does not override it. [store_updates.rs](../store_updates.rs) rejects direct builds, initializes StoreContext with the Settings window as its dialog owner on the UI thread, and asks the Store for available packages or installation. [window_commands.rs](../window_commands.rs) refuses to open the GitHub release page when packaged.

The command and event boundary is used by [frontend code](../../../src/doc/architecture.md). [default.json](../../capabilities/default.json) lists frontend permissions. Unit tests cover settings validation, add-on kind/action contracts, cleanup rules, Timer resume/completion, hotkey parsing and font enumeration. The font list is read on request, while only the selected family name is persisted. These built-in add-ons do not load third-party code or network data.
